Work down this list. The order matters: several of these are much harder to change
once learners exist.

<WhoCan roles="Admin" />

## Before you build anything

| Check | Why now |
|---|---|
| **Academy name, logo (light and dark), social share image** | They appear everywhere, including on certificates. |
| **Custom domain** | Every link shared carries the address people first saw. |
| **Organisation email** | It is what learners are told to contact. |
| **Certificate number pattern** | Certificates keep the number they were issued with. |
| **Student ID pattern** | Easier before a thousand learners than after. |
| **One identifier for registration** | Allowing email *and* phone produces duplicates you cannot merge. |
| **Lock the name field** | A learner who can edit their name can edit their certificate. |

[Your platform's identity](/docs/knowledgebase/account-people/your-platform-settings) ·
[The Control Panel](/docs/knowledgebase/settings/control-panel)

## Connect the services

| Check | Why |
|---|---|
| **An email service, tested** | Verification, password resets and receipts all depend on it. |
| **A payment gateway, in live mode** | A gateway left in test takes payments that are not real. |
| **SMS, if your learners read texts** | In Bangladesh, often the difference between reaching them and not. |

[Channels](/docs/knowledgebase/communication/channels) ·
[Payment methods](/docs/knowledgebase/selling-payments/payment-methods)

## Build one course properly

| Check |
|---|
| The right [course type](/docs/knowledgebase/courses/course-types) — it cannot be changed |
| Every item that should be live has its **Published** switch on |
| A [grading scheme](/docs/knowledgebase/progress-grading/grading-schemes) with no gaps between bands |
| [Weights](/docs/knowledgebase/progress-grading/weighted-grading) totalling 100% |
| [Completion rules](/docs/knowledgebase/progress-grading/completion-rules) that are reachable |
| A [certificate type](/docs/knowledgebase/certificates/certificate-types) with the right passing basis |
| A **price** — published is not for sale |
| For cohort-based: **at least one batch**, with dates and seats |

## Write the messages

Eight templates cover most of a year:

welcome · payment confirmation · payment reminder · course starting ·
assignment due · results published · certificate earned · access ending

And one setting: **Exclude Transactional from Limits**, so a marketing cap can never
block a verification email.

[Message templates](/docs/knowledgebase/communication/message-templates) ·
[Notification settings](/docs/knowledgebase/communication/notification-preferences)

## The website

| Check |
|---|
| **Allow search engines to index this site** is **on** |
| Site state is **Live** |
| Course lists use a **Courses block**, not typed text |
| Legal pages exist, and privacy settings point at them |
| Checked on a phone |

[Publishing your site](/docs/knowledgebase/website/publishing) ·
[SEO](/docs/knowledgebase/website/seo)

## The one that finds everything else

<Callout type="warn">
**Register a fresh account and buy your course, start to finish.**

Not as an admin. A new account, a real payment, the verification email, the first
lesson. Twenty minutes, and it finds the missing price, the gateway in test mode, the
verification email that never arrives and the empty checkout page — all of which your
first real customer would have found instead.
</Callout>

## After launch, weekly

1. **Payments waiting to be checked** — people who paid and cannot get in.
2. **Instalments overdue** — money owed.
3. **Reported problems** — things learners say are broken.
4. **Ungraded submissions** — work waiting on you.
5. **Pending refund requests** — decisions waiting on you.
