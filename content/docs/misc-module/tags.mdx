# Tags

**Tags** are lightweight, flat labels used to mark content across EduShade with descriptors like `#beginner`, `#new`, `#featured`, or tenant-specific keywords. Unlike [categories](/docs/knowledgebase/misc-module/categories), tags have **no hierarchy** — every tag is a peer of every other tag.

Tags are tenant-scoped, can have a color and a status, and can be attached to a wide range of entities via [Tag Associations](/docs/knowledgebase/misc-module/tag-associations).

## Accessing Tags

1. Sign in as an administrator with tag management permissions.
2. Navigate to **Admin → Tags** (`/admin/tags`).
3. Required permissions:
   - `tag.list` — view the list
   - `tag.view` — open a single tag or its stats
   - `tag.create` — create new tags
   - `tag.update` — edit tags or attach/detach associations
   - `tag.delete` — delete tags

## Tag Data Model

Every tag has the following fields:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | UUID | auto | Primary key |
| `tenant_id` | UUID | auto | Tenant scope |
| `title` | string (1–255) | Yes | Display title |
| `slug` | string (1–255) | Yes | URL-friendly slug, unique per tenant |
| `description` | text (0–1000) | No | Optional description |
| `status` | enum | Yes on create | `published`, `draft`, `archived` — `CreateTagDto` requires this field (the DB column default is `draft`, but validation rejects missing values) |
| `color` | string (exactly 7 chars) | No | Hex color `#RRGGBB` for the tag badge |
| `created_by` | UUID | auto | User ID of creator |
| `updated_by` | UUID | auto | User ID of last editor |
| `created_at` / `updated_at` | timestamp | auto | Audit timestamps |
| `deleted_at` | timestamp | auto | Soft-delete marker |

> `status` is **required** on create (`CreateTagDto` fails validation when it's missing). The database column default (`draft`) only applies if a row is inserted outside the validated path — under normal use you must pick a status explicitly.

## Tag List

A searchable, filterable, paginated table of all tags (`GET /api/v1/admin/tags`).

### Available Columns

- **Title**
- **Slug**
- **Status** badge
- **Color** — a swatch showing the current `color` value
- **Created at**

Row click and the **Edit** action both open the edit page; rows also expose a **Delete** action.

### Filtering Tags

The tag list backs onto the `TagFilterDto`. Filters combine freely.

| Filter | Query param | Description |
|--------|-------------|-------------|
| **Search** | `search` | Case-insensitive ILIKE match on `title` |
| **Status** | `status` | One of `published`, `draft`, `archived` |
| **Entity type** | `entity_type` | Only tags attached to entities of this type |
| **Entity ID** | `entity_id` | Combined with `entity_type` — only tags attached to this specific entity |
| **Include IDs** | `include_ids` | Comma-separated UUIDs to prioritize at the top of the first page (for preselected dropdown values) |

### Sorting & Pagination

| Param | Default | Notes |
|-------|---------|-------|
| `page` | `1` | |
| `per_page` | `100` | |
| `sort_by` | `created_at` | Any tag column |
| `sort_dir` | `desc` | `asc` or `desc` |

## Creating a Tag

1. Click **Create Tag** at `/admin/tags/create` (requires `tag.create`).
2. Fill the form:

| Field | Required | Notes |
|-------|----------|-------|
| **Title** | Yes | 1–255 chars. The slug auto-fills as you type. |
| **Slug** | Yes | 1–255 chars. Unique per tenant. Editable after auto-fill. |
| **Description** | No | Up to 1000 chars. |
| **Color** | No | 7-char hex `#RRGGBB`. |
| **Status** | Yes | `published`, `draft`, or `archived`. Validation rejects missing values. |

3. Click **Save**.

API: `POST /api/v1/admin/tags`. Returns the created tag.

### Slug Uniqueness

- Slug uniqueness is enforced per tenant via a unique index on (`tenant_id`, `slug`).
- Duplicate slug returns `400 Bad Request`.
- The slug is **required** on create — unlike categories (which have a Bun `BeforeAppendModel` hook that generates a slug from the title when missing), the tag model has no such hook. `CreateTagDto` also declares `slug` as `validation.Required`, so omitting it fails validation. The frontend auto-fills the slug from the title before submit.

### Events Published on Create

- `AuditEvent` with `action = "created"`, `resource_type = "tag"`, `module = "misc"`

> Unlike categories, tags **do not** publish `EntityCreated` / `EntityUpdated` / `EntityDeleted` events. Only audit events are emitted.

## Viewing a Tag

Two lookup endpoints exist:

| By | Endpoint | Permission |
|----|----------|------------|
| ID | `GET /api/v1/admin/tags/{tag_id}` | `tag.view` |
| Slug | `GET /api/v1/admin/tags/slug/{slug}` | `tag.view` |

Both return the tag object or `404`.

The slug endpoint is useful for URL-driven admin flows where you want to look up a tag by a human-readable path.

## Editing a Tag

1. Open `/admin/tags/{id}/edit` (requires `tag.update`).
2. All fields are optional on edit — only the ones you send are updated:

| Field | Validation |
|-------|------------|
| `title` | 1–255 chars |
| `slug` | 1–255 chars, unique per tenant (excluding current id) |
| `description` | 0–1000 chars |
| `color` | exactly 7 chars, hex |
| `status` | `published` / `draft` / `archived` |

3. Click **Save**.

API: `PUT /api/v1/admin/tags/{tag_id}`.

### Events Published on Update

- `AuditEvent` with `action = "updated"`

## Deleting a Tag

1. Click **Delete** in the row or from the edit page (requires `tag.delete`).
2. Confirm.
3. The tag is **soft-deleted** — `deleted_at` is set, the tag disappears from listings, and all lookups return `404`.

API: `DELETE /api/v1/admin/tags/{tag_id}` — returns `204 No Content` on success.

### Existing Associations

Tag associations (`tag_associations`) have `ON DELETE CASCADE` on `tag_id`, so physically deleting a tag row removes its associations. Soft delete (the normal path) leaves associations intact — they keep pointing at the soft-deleted record until you purge it from the DB manually.

### Events Published on Delete

- `AuditEvent` with `action = "deleted"`

## Tag Statistics

Find out how many entities currently have a given tag.

- API: `GET /api/v1/admin/tags/{tag_id}/stats` (requires `tag.view`)

Returns a `TagStatsDto`:

| Field | Description |
|-------|-------------|
| `tag_id` | The tag ID |
| `tag_title` | Display title |
| `entity_counts` | Map of `entity_type → count` |
| `total_count` | Sum of all entity counts |

### Entity Types Counted

Stats run a count per type across the following known entity types:

- `product`
- `course`
- `event`
- `learning_path`
- `bundle`
- `lesson`
- `assignment`
- `cohort`
- `user`
- `post`
- `article`

Only entity types with **at least one** attached association are written into `entity_counts` — the service skips zero counts entirely, so if a tag has no products attached, the response will not contain a `product` key at all (not `product: 0`). Consumers should treat missing keys as zero, not as "not supported".

If your service uses a custom `entity_type` string, the stats endpoint won't include it automatically — the list above is hard-coded in the service. Query `tag_associations` directly if you need extended coverage.

## Status Lifecycle

| Status | Behavior |
|--------|----------|
| `draft` | Shows in admin listings; hidden from any public surfaces that filter on status |
| `published` | Live — shows everywhere |
| `archived` | Retired but retained — hidden from public-facing consumers |

Status is orthogonal to soft delete. A soft-deleted tag is gone regardless of its status.

## Frontend Notes

The tag admin UI lives at:

| Page | Path |
|------|------|
| Tags list | `/admin/tags` |
| Create tag | `/admin/tags/create` |
| Edit tag | `/admin/tags/{id}/edit` |

Validation is client-side (Zod schema in `frontend/src/lib/tags/schema.ts`) and re-enforced server-side.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| "Slug already exists" | Pick a different slug, or purge the soft-deleted record |
| Stats show `0` for an entity type I know I tagged | Confirm the entity type matches exactly — tag stats only count the known entity types listed above |
| Expected entity type missing from `entity_counts` | Stats omit zero-count keys entirely — an absent key means `0`, not "unsupported". Double-check an actual association exists. |
| Tags don't show up in the public site | There's no public tag endpoint — consumers that want public tags must expose them via their own endpoint (e.g. course catalog returns the course's tags in its own payload) |
| Can't see Tags in sidebar | Verify you have `tag.list` on one of your roles |
| Delete didn't return anything | Delete returns `204 No Content` — that is success |
| Edit fails with `404` | Tag may have been soft-deleted |
