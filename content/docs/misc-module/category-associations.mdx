# Category Associations

A **category association** is a link between a category and any other entity in the platform. Associations are **polymorphic** — the association table stores an `entity_type` string (e.g. `"course"`, `"event"`) plus an `entity_id`, so a single category can be attached to many different kinds of entities without schema changes on either side.

## Association Data Model

**Table:** `category_associations`

| Field | Type | Description |
|-------|------|-------------|
| `id` | UUID | Primary key |
| `tenant_id` | UUID | Tenant scope |
| `category_id` | UUID | Reference to `categories.id` (cascade delete) |
| `entity_type` | string (≤50) | e.g. `"course"`, `"event"` — defined by the consuming service |
| `entity_id` | UUID | ID of the entity being categorized |
| `created_at` | timestamp | When the association was created |

### Uniqueness

A unique constraint covers (`category_id`, `entity_type`, `entity_id`) — you cannot attach the same category to the same entity twice. Attempting to is a no-op at the service layer; duplicates are silently skipped.

### Foreign-Key Behavior

`category_id` is a foreign key to `categories.id` with `ON DELETE CASCADE`. If a category row is **physically** deleted, its associations vanish with it. Soft delete (the normal case) leaves associations in place — see [Categories → Deleting a Category](/docs/knowledgebase/misc-module/categories#existing-associations).

## REST API — Single Association

There are two endpoints, one to attach and one to detach. Both work on a single `(category, entity_type, entity_id)` triple.

### Create Association

- **Endpoint:** `POST /api/v1/admin/categories/{category_id}/associations/{entity_type}/{entity_id}`
- **Permission:** `category.update`
- **Path params:**
  - `category_id` — the category to attach
  - `entity_type` — free-form string, typically one of `course`, `event` (see [Supported Entity Types](#supported-entity-types))
  - `entity_id` — UUID of the entity
- **Body:** none
- **Returns:** `201 Created` with a success message
- **Events:** `AuditEvent` with `action = "created"`, `resource_type = "category_association"`, `resource_id = category_id`, `module = "misc"`

If the association already exists, the endpoint is idempotent — no error, no duplicate row (the unique constraint on `(category_id, entity_type, entity_id)` plus the service's duplicate-skip logic keep things clean).

### Delete Association

- **Endpoint:** `DELETE /api/v1/admin/categories/{category_id}/associations/{entity_type}/{entity_id}`
- **Permission:** `category.update`
- **Path params:** same as above
- **Returns:** `200 OK` with a success message
- **Events:** `AuditEvent` with `action = "deleted"`, `resource_type = "category_association"`, `resource_id = category_id`, `module = "misc"`

If the association doesn't exist, the operation is a no-op and returns success.

## Service-Level Helpers (Batch Operations)

For services integrating directly against the misc DB, `CategoryAssociationService` exposes a richer set of operations that are **not exposed as HTTP endpoints today** — they're consumed by other Go services through internal service calls.

| Method | Purpose |
|--------|---------|
| `Attach(tenantID, entityType, entityID, categoryIDs)` | Attach many categories to one entity in one call; duplicates are skipped |
| `Detach(tenantID, entityType, entityID)` | Remove **all** category associations for a given entity |
| `Remove(tenantID, entityType, entityID, categoryIDs)` | Remove a specific set of categories from an entity |
| `Sync(tenantID, entityType, entityID, categoryIDs)` | Replace the entity's categories with exactly the given list (detach old + attach new in one call) |
| `Exists(tenantID, categoryID, entityType, entityID)` | Check whether a specific association exists |
| `GetCategoriesByEntity(tenantID, entityType, entityID)` | Fetch every category attached to one entity |
| `GetPublishedCategoriesByEntity(tenantID, entityType, entityID)` | Same, but filtered to `status = published` |
| `GetCategoriesByEntities(tenantID, entityType, entityIDs)` | Batch fetch categories for many entities — returns `map[entityID] → []Category` |
| `GetPublishedCategoriesByEntities(...)` | Batch fetch, published only |
| `GetEntityIDsByCategory(tenantID, entityType, categoryIDs)` | Reverse lookup — find every entity of a given type that has any of these categories |

When a course/event/etc. service needs to power its own "browse by category" UI, it typically calls one of the batch helpers.

## Filtering Categories by Attached Entity

The `CategoryFilterDto` exposes `entity_type` and `entity_id` query parameters, **but the category service currently ignores them** — they do not filter the SQL query:

```
GET /api/v1/admin/categories?entity_type=course&entity_id=<uuid>
# Returns the full list, unfiltered by attachment
```

If you need "categories attached to entity X" today, you have two working options:

1. Query `category_associations` directly (either through the misc DB or via a service-level join), or
2. Ask the owning service (e.g. the course service) for its categories — it typically returns them inline with the entity.

The DTO also **validates `entity_type` against `"course"` or `"event"` only**, so even if a fix re-enables the filter it will refuse other entity types at the list endpoint without a schema change.

> Tag listing **does** honor `entity_type` + `entity_id` via a join on `tag_associations` — see [Tag Associations](/docs/knowledgebase/misc-module/tag-associations#filtering-tags-by-attached-entity).

## Filtering Entities by Category (Reverse Lookup)

The reverse question — "Give me every course that has category X" — is answered by the consuming service, not the misc service. The consumer either:

1. Calls `GetEntityIDsByCategory` on the association service and then fetches the entity rows itself, or
2. Joins `category_associations` directly if it shares a database boundary.

Misc-service does not expose an HTTP endpoint for "list entities by category" — that responsibility stays with each consumer (e.g. the course-service's own catalog endpoint accepts a `category_id` filter).

## Supported Entity Types

The **associations endpoints** (`POST` / `DELETE /associations/{entity_type}/{entity_id}`) don't validate `entity_type` — any string up to 50 chars is accepted by the DB column, and the `Attach`/`Remove` service methods pass the value straight through. In practice the platform currently uses:

| Entity type | Owner service | Typical UI |
|-------------|---------------|-----------|
| `course` | Learning | Course edit form → Categories selector |
| `event` | Events | Event edit form → Categories selector |

Two related-but-separate validations to keep in mind:

- The **category list filter** DTO restricts `entity_type` to `"course"` or `"event"` (it will `400` other values) — but that filter is not even applied to the query today, so it doesn't affect real behavior.
- **Category stats** only counts `course` and `event` — hard-coded in `GetCategoryStats`. If you add another entity type, its associations still save but won't show up in stats.

Tag statistics (see [Tags](/docs/knowledgebase/misc-module/tags)) iterate over a wider known list; categories are intentionally narrower because hierarchical classification makes less sense for lightweight content like posts.

## Events on Attach / Detach

Both `Create Association` and `Delete Association` publish an `AuditEvent` with:

- `resource_type = "category_association"` (distinct from the `"category"` used by category CRUD)
- `resource_id = category_id`
- `action = "created"` or `"deleted"`
- `module = "misc"`
- Description includes the entity type and ID for traceability (e.g. `"Associated category with course <uuid>"`)
- On create, `after_value` includes `{ "category_id", "entity_type", "entity_id" }`
- Actor, IP address, user agent, and timestamp are populated from the request context

Unlike Create/Update/Delete of the category itself, attach/detach does **not** publish an `EntityCreated`/`EntityUpdated`/`EntityDeleted` event — only an audit record.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Attach returns `201` but list still doesn't show it | Check `tenant_id` — cross-tenant queries return empty |
| Attach seems to succeed twice but only one row is visible | Expected: duplicates are silently skipped by the unique constraint |
| Deleting an entity didn't remove its categories | Associations only cascade on **category** deletion, not on the entity — the owning service is responsible for cleaning up its own associations on entity delete |
| Bulk UI sync behaves oddly | The HTTP API has no batch/sync endpoint; the frontend must call Attach / Delete one at a time, or the owning service must call `Sync` on its Go client directly |
| Permission denied | Attaching or detaching requires `category.update`, not `category.create`/`category.delete` — this is intentional because the category itself is not being mutated |
