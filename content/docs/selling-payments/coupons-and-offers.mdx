An offer is a discount code. A buyer types it at checkout and the price drops.

Offers live in <Path>Billing > Offers & Promotions > All Offers</Path>.

<Callout type="warn">
**A code has to be typed in.** There is no automatic discount — nothing applies itself
because a date arrived or a basket qualified. Every offer needs the buyer to enter its
code. Plan your campaigns around that: the code has to reach them, and they have to
remember it at checkout.
</Callout>

<WhoCan roles="Admin" />

## Building an offer

| Field | What it is |
|---|---|
| **Title** | For your own list. |
| **Description** | A note. |
| **Amount Type** | **Percentage**, **Fixed Amount** or **Full Amount**. |
| **Max amount limit** | A ceiling on a percentage discount — "20% off, up to ৳1,000". |
| **Available currencies** | Which currencies it works in. |
| **Start Date** / **End Date** | When it is live. |
| **Status** | Active or not. |

**Full Amount** makes the purchase free. Use it for a complimentary place rather than
building a 100% percentage offer.

## The code

| Field | What it is |
|---|---|
| **Code Generation Type** | A **manual** code you choose, or generated ones. |
| **Manual Code** | The code itself — `EARLYBIRD`, `RAMADAN25`. |
| **Code Prefix** / **Code Length** | For generated codes. |

Generated codes give every recipient their own — which is how you tell who actually
used the offer you sent them, and stop a single code spreading.

## Who and what it applies to

**Applicable To** narrows the offer:

| Choice | Effect |
|---|---|
| **All courses**, **All Bundles**, **All Events**, **All Learning Path**, **All Products**, **All Meeting Plans** | Everything of that type. |
| **Select specific…** | Only the ones you pick. |

## Limits

| Limit | What it stops |
|---|---|
| **Total Usage Limit** | How many times the offer may be used at all. |
| **Max Usage Per Customer** | How many times one person may use it. |
| **Minimum Purchase Amount** | The total below which it will not apply. |

**Max Usage Per Customer** matters more than it looks. Without it, one buyer can use a
generous code repeatedly.

## Watching an offer

Each offer has a **usage** view: who used it, on what, when, the discount given and the
payment behind it. It is how you tell whether a campaign worked, and whether a code has
leaked somewhere it should not have.

## Common questions

<Accordions type="single">

<Accordion title="A learner says the code does not work.">
Work down: is it active, has it started, has it ended, is it applicable to what they are
buying, is the purchase above the minimum, has the total usage limit been reached, and
have they already used it as many times as allowed.
</Accordion>

<Accordion title="Can I apply a discount without a code?">
Not as an offer. Use the **Regular amount** on the price to show a struck-through
original — see [Pricing](/docs/knowledgebase/selling-payments/pricing) — or record the
discount yourself on a [manual payment](/docs/knowledgebase/selling-payments/manual-payments).
</Accordion>

<Accordion title="Can two codes be used together?">
One per checkout.
</Accordion>

<Accordion title="A code is being shared publicly.">
Set its status inactive and issue generated codes instead, so each recipient has their
own.
</Accordion>

<Accordion title="What is the difference between an offer and a scholarship?">
An offer is a discount anyone with the code can use. A
[scholarship](/docs/knowledgebase/selling-payments/scholarships) is granted to a named
learner, usually after they apply.
</Accordion>

</Accordions>
