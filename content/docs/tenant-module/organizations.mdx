# Organizations

An **organization** is the legal, commercial, and hierarchical container that owns one or more [tenants](/docs/knowledgebase/tenant-module/tenants). A single enterprise customer is typically modelled as one root organization with a small tree of child organizations (departments, subsidiaries, branches, teams) and one or more tenants attached at whichever level matches how they want to scope branding and access.

Organizations themselves do not have a URL or admin surface — users log into **tenants**, not organizations. But because RBAC inside the tenant service is scoped partly by organization (via `organization_members`) and because tenant-level permissions can be assumed from `organization.manage`, understanding the org hierarchy matters as much as understanding tenants.

## Data Shape

**Table:** `organizations`

| Field | Type | Description |
|-------|------|-------------|
| `id` | UUID | Primary key |
| `name` | string (1–255) | Display name, required |
| `code` | string (1–100), nullable, **unique** | Globally unique short code. Uppercased + trimmed on write, matched case-insensitively |
| `description` | string (0–5000), nullable | Free-text description |
| `type` | string, nullable | One of `company`, `department`, `division`, `subsidiary`, `branch`, `team`. The DTO also accepts `enterprise` and `individual` for historical reasons, but the model only defines constants for the six in this list — `enterprise` and `individual` are accepted without constants |
| `email`, `phone`, `website`, `address` | string, nullable | Contact block. `email` validated with `is.Email`, `website` with `is.URL` |
| `country`, `state`, `city`, `postal_code` | string, nullable | Location block |
| `parent_id` | UUID, nullable | Optional pointer to a parent organization row |
| `status` | string | One of `active`, `inactive`, `archived`. Defaults to `active` |
| `metadata` | JSONB, nullable | Free-form per-org metadata |
| `created_at` / `updated_at` | timestamp | Auto-managed by `BeforeAppendModel` hook |
| `deleted_at` | timestamp, nullable | Soft-delete marker |

## Route Tiers

Organization endpoints are exposed on two of the four tiers:

- **Sysadmin** (`/api/v1/sysadmin/organizations/…`) — full CRUD across all organizations
- **Org-admin** (`/api/v1/orgadmin/organizations/:organization_id/…`) — restricted to a single organization the signed-in user is a member of

Tenant-admin and public tiers do **not** expose organizations directly — tenant admins interact with their organization only through their tenant settings.

## Create an Organization

- **Sysadmin endpoint:** `POST /api/v1/sysadmin/organizations`
- **Auth:** Sysadmin

### Request

```json
{
  "name": "Acme Corp",
  "code": "ACME",
  "description": "Global learning organization",
  "type": "company",
  "email": "ops@acme.com",
  "phone": "+1-555-0100",
  "website": "https://acme.com",
  "address": "1 Acme Way",
  "country": "US",
  "state": "CA",
  "city": "San Francisco",
  "postal_code": "94107",
  "parent_id": null,
  "status": "active",
  "metadata": { "industry": "education" }
}
```

| Field | Rules |
|-------|-------|
| `name` | Required, 1–255 chars |
| `code` | Optional, 1–100 chars, `^[a-zA-Z0-9_-]+$`, **globally unique** (case-insensitive) |
| `description` | Optional, 0–5000 chars |
| `type` | Optional, one of `company`, `department`, `division`, `subsidiary`, `branch`, `team` (or `enterprise`, `individual`) |
| `email` | Optional, 0–255 chars, valid email |
| `website` | Optional, 0–500 chars, valid URL |
| Other contact/location fields | Optional length limits per field |
| `parent_id` | Optional UUID. If set, the parent organization must exist |
| `status` | Optional, one of `active`, `inactive`, `archived`. Defaults to `active` |
| `metadata` | Optional JSON object |

### What happens

1. If `code` is set, it is uppercased + trimmed and checked for global uniqueness → `409 Conflict` with `organization with code '<X>' already exists`.
2. If `parent_id` is set, the parent is resolved → `500` with `parent organization not found` if missing.
3. The row is inserted and an `AuditEvent { action: "created", resource_type: "organization" }` is published.

## Retrieve an Organization

| Scope | Endpoint |
|-------|----------|
| Sysadmin | `GET /api/v1/sysadmin/organizations/:id` |
| Org-admin | `GET /api/v1/orgadmin/organizations/:organization_id` (scoped to that one org) |

The org-admin endpoint requires `organization.view` or `organization.manage` — the `CanAnyWithOrganization` middleware checks membership + the permission set on the signed-in user's roles inside that org.

## List Organizations

- **Endpoint:** `GET /api/v1/sysadmin/organizations`
- **Auth:** Sysadmin

Query params:

| Param | Description |
|-------|-------------|
| `status` | One of `active`, `inactive`, `archived` |
| `type` | One of `company`, `department`, `division`, `subsidiary`, `branch`, `team` (or `enterprise`, `individual`) |
| `parent_id` | UUID — return only direct children of this organization |
| `search` | Case-insensitive `LIKE` on `name`, `code`, or `description` |
| `page`, `per_page`, sort params | Standard pagination |

There is no "tree" endpoint — callers that want a tree should either:

1. Query roots with `parent_id=<empty-uuid-marker>` and walk via `GET /:id/children`, or
2. List everything and build the tree client-side from `parent_id`.

## Update an Organization

| Scope | Endpoint |
|-------|----------|
| Sysadmin | `PUT /api/v1/sysadmin/organizations/:id` |
| Org-admin | `PUT /api/v1/orgadmin/organizations/:organization_id` (own org only) |

Permissions (org-admin): `organization.update` or `organization.manage`.

All fields are optional. Only provided fields are changed.

### Parent handling

Updating `parent_id`:

- Empty string (`""`) clears the parent — the organization becomes a root.
- A UUID:
  - **Self-parent is rejected:** `"organization cannot be its own parent"` → `409 Conflict`.
  - **The parent must already exist.**
  - **A one-level circular reference is rejected:** if the prospective parent's own `parent_id` is this organization, the update fails with `"circular reference detected"` → `409 Conflict`.
  - Deeper cycles (A → B → C → A) are **not** prevented by the API — the check only looks one hop up. Avoid cycles in the client.

### Code handling

If `code` changes, uniqueness is re-checked (case-insensitive, global) → `409 Conflict` on collision.

### Status values

Status accepts `active`, `inactive`, `archived`. `archived` is typically used for legal wind-downs where the org should not show up in active filters but the row should be preserved for audit.

## Delete an Organization

| Scope | Endpoint |
|-------|----------|
| Sysadmin | `DELETE /api/v1/sysadmin/organizations/:id` |

Performs a **soft delete** with two refusal guards:

| Guard | Response |
|-------|----------|
| Organization has any **child organizations** (via `parent_id`) | `409 Conflict` — `cannot delete organization with child organizations` |
| Organization has any **tenants** (via `tenants.organization_id`) | `409 Conflict` — `cannot delete organization with tenants` |

Delete or reassign all children and detach all tenants first. There is no bulk / cascading delete.

Publishes `AuditEvent { action: "deleted", resource_type: "organization" }`.

## Hierarchy Queries

### Direct children

- **Endpoint:** `GET /api/v1/sysadmin/organizations/:id/children`
- **Endpoint:** `GET /api/v1/orgadmin/organizations/:organization_id/children`
- **Permissions (org-admin):** `organization.view` or `organization.manage`

Returns all organizations whose `parent_id` equals the given ID, ordered by `name ASC`. One level only — to traverse further, call this endpoint again for each child.

### Tenants of an organization

- **Endpoint:** `GET /api/v1/sysadmin/organizations/:id/tenants`

Returns all tenants whose `organization_id` equals the given ID, ordered by `name ASC`. Returns both active and non-active tenants; filter at the caller.

> The org-admin tier lists tenants through its own `GET /orgadmin/organizations/:organization_id/tenants` endpoint — see [Tenants → List Tenants](/docs/knowledgebase/tenant-module/tenants#list-tenants).

## Organization Statistics

- **Endpoint:** `GET /api/v1/sysadmin/organizations/stats`
- **Auth:** Sysadmin

Returns the platform-wide roll-up shown on the sysadmin dashboard:

| Field | Meaning |
|-------|---------|
| `total_organizations` | All non-deleted organizations |
| `active_organizations` / `inactive_organizations` / `archived_organizations` | Count by `status` |
| `new_organizations_last_30_days` | `created_at >= now() - 30d` |
| `new_organizations_prev_30_days` | `created_at` in `[now-60d, now-30d)` |
| `organizations_by_type` | Map of `{ type: count }` — populated via a `GROUP BY type` where `type IS NOT NULL` |
| `organizations_with_parent` | Count where `parent_id IS NOT NULL` |
| `root_organizations` | Count where `parent_id IS NULL` |

## Troubleshooting

| Issue | Solution |
|-------|----------|
| `code already exists` on create | Codes are globally unique, case-insensitive, and uppercased server-side. Pick a different code or update the existing org |
| `cannot delete organization with child organizations` | Delete or reparent every child first. The guard rejects even if children are `inactive` or `archived` |
| `cannot delete organization with tenants` | Detach or delete every tenant under this org first. Soft-deleted tenants still count until hard-deleted at the DB |
| Circular hierarchy went through | The parent check only looks one hop up. If your UI allows deep reparenting, run a client-side cycle check before the PUT |
| Org-admin gets `403` on their own org | The signed-in user has no `organization_members` row in that org, or their roles don't include `organization.view` / `organization.manage`. Add them as a member with an appropriate role |
