A menu is a list of links. Your header has one, your footer usually has another.

<Path>Configure > Website</Path>, under menus.

<WhoCan roles="Admin" />

## Building one

**Add Items** puts links in. Each item has a **Navigation Label** — what visitors read —
and a destination: one of your pages, or an address of your own.

| Control | What it does |
|---|---|
| **Indent right (make child)** | Puts the item under the one above, as a dropdown entry. |
| **Indent left (make parent)** | Brings it back out. |
| **Add child item** | Adds an entry under this one. |
| **Remove item** | Takes it out. |
| Drag | Reorders. |

## Keeping it short

<Callout type="info">
**Five items in a header is plenty.** Seven is too many, and on a phone everything goes
behind a menu button anyway — so the order matters more than the length.
</Callout>

A header that works for a course business:

```
Courses
Programmes       (if you run learning paths)
About
Contact
Sign in / My learning
```

Everything else — terms, privacy, social links, contact details — goes in the footer,
where people look for it.

## Where menus are used

Menus are shown by the **Header** and **Footer** blocks, which are set site-wide in
your website settings. Change the menu and every page follows.

## Common questions

<Accordions type="single">

<Accordion title="A menu item leads nowhere.">
Its page was deleted or its address changed. Point it at the right page, and set a
[redirect](/docs/knowledgebase/website/versions-and-redirects) if people have the old
address.
</Accordion>

<Accordion title="Can a menu item open in a new tab?">
Set it on the item, for links leaving your site.
</Accordion>

<Accordion title="Can the menu differ for signed-in learners?">
The menu is the site's. Learners have their own dashboard navigation once signed in —
see [The learner experience](/docs/knowledgebase/learner).
</Accordion>

<Accordion title="How deep can menus nest?">
One level of children is what visitors can follow. Deeper is a menu nobody uses.
</Accordion>
