# Search Bar

The **`SearchBar`** is the primary entry point to search across the platform's public-facing surfaces. It renders a button trigger that opens a command-palette dialog with typeahead suggestions, the user's recent searches, trending queries, and an inline results view.

Component path: `website-builder-v2/src/components/website/search/search-bar.tsx`

## What It Does

Opening the dialog shows one of three view states depending on the user's input:

| Input state | What renders |
|-------------|--------------|
| Empty input, user has recent searches | **Recent Searches** list + **Trending** list below it |
| Typing (≥ 2 chars) | **Suggestions** list (autocomplete), plus a "Search for …" fallback item |
| Submitted query (Enter, or clicked suggestion/history/trending row) | Inline **Search Results** view with a back button to return to suggestions |

## How It Works

**Props:**

| Prop | Type | Description |
|------|------|-------------|
| `onResultClick` | `(result: SearchResult) => void` | Optional callback fired when a result is clicked (in addition to navigation) |
| `className` | `string` | Forwarded to the trigger `<Button>` |
| `triggerContent` | `React.ReactNode` | Optional custom contents for the trigger button. Defaults to the `Search` icon |

**Steps:**

1. The user clicks the trigger button — the `CommandDialog` opens.
2. Input is **debounced by 300 ms** before being forwarded to the autocomplete API.
3. While the debounced query is empty, the dialog fetches:
   - **Recent searches** (`getSearchHistory({ page: 1, per_page: 5 })`)
   - **Trending searches** (`getTrendingSearches({ limit: 5 })`)
4. Once the debounced query is **≥ 2 characters**, it fetches **autocomplete** (`getAutocomplete({ q, limit: 5 })`) instead.
5. Pressing **Enter** (or clicking a suggestion / history row / trending row / the "Search for …" fallback) switches the dialog into the results view, rendering `<SearchResults query={searchQuery} />`.
6. Inside the results view, the dialog shows a small header with the query and a **back (X)** button that clears the query and returns to the suggestions view.
7. Closing the dialog resets query, search query, and results state.

## API Calls Made

| Condition | Method | Endpoint |
|-----------|--------|----------|
| Dialog open, input empty | `apiClient.getSearchHistory` | `GET /api/v1/public/search/history` |
| Dialog open, input empty | `apiClient.getTrendingSearches` | `GET /api/v1/public/search/trending` |
| Input ≥ 2 chars (debounced) | `apiClient.getAutocomplete` | `GET /api/v1/public/search/autocomplete` |
| Query submitted | Handled by [`SearchResults`](/docs/knowledgebase/search-module/search-results) | `GET /api/v1/public/search` |
| Delete single history row | `apiClient.deleteSearchHistoryEntry` | `DELETE /api/v1/public/search/history/:id` |
| Clear all history | `apiClient.clearSearchHistory` | `DELETE /api/v1/public/search/history` |

All methods accept an `isAdmin: boolean` flag; when `true`, they hit `/api/v1/admin/search/...` instead. See [Admin Search](/docs/knowledgebase/search-module/admin-search).

## Recent Searches Section

- Shows up to **5 most recent** queries when the input is empty.
- Each row shows a clock icon and the query string, selecting it triggers a new search.
- Hovering a row reveals an **X** button — clicking it deletes that single history entry (invalidates the `search-history` query in React Query so the list refreshes).
- When there are more than one entry, a **Clear All** button appears in the section header. Clicking it opens a confirmation dialog (`"Clear all search history?"`) before issuing a `DELETE /history` call.

See [Search History](/docs/knowledgebase/search-module/search-history) for how entries are stored, scoped, and deduplicated.

## Trending Section

- Shows up to **5 queries** with the highest growth rate over the default 7-day window.
- Only renders when the user has no typed query and no recent searches are being displayed; it's purely a cold-start helper.
- Each row shows a **trending-up** icon followed by the query; clicking it runs the search.

See [Trending Searches & Results](/docs/knowledgebase/search-module/trending) for how growth is computed.

## Suggestions Section (Autocomplete)

- Activated once the debounced query is **≥ 2 characters**.
- Each suggestion is rendered with `dangerouslySetInnerHTML` on the `highlight` field so the match can be visually emphasised (typically wrapped in `<mark>`).
- If the server returns **no suggestions** for a query ≥ 2 chars, a single fallback row "Search for \"{query}\"" is rendered — clicking it opens the full results view for that literal query.

See [Autocomplete](/docs/knowledgebase/search-module/autocomplete) for the underlying endpoint.

## Locale Awareness

The component reads the current locale from `useLocale()` and includes it in every React Query `queryKey`:

- `["search-autocomplete", autocompleteQuery, locale]`
- `["search-history", locale]`
- `["trending-searches", locale]`

Switching locale therefore invalidates the caches and re-fetches so the rendered highlights and suggestion strings match the active language.

## Keyboard Behaviour

| Key | Behaviour |
|-----|-----------|
| Arrow up / down | Move selection between Command items (provided by the underlying `Command` primitive) |
| Enter | If typed query ≥ 2 chars, submit the search (opens results view) |
| Esc | Close the dialog |

## Styling & Integration

- The dialog width caps at `sm:max-w-2xl` and the inline results area caps at `max-h-[500px]` with overflow scroll.
- The component toggles a single internal `open` state — there is no external "controlled" API; the dialog is owned by the trigger.
- To render the bar inside a site header, pass a custom `triggerContent` (e.g. a full-width "Search…" pill). This is what the `search_bar` action does in the Taibah header blocks. See [Search Integration](/docs/knowledgebase/search-module/search-integration).

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Suggestions never load | Confirm the debounced query has reached the 2-character threshold; the hook is disabled below that length |
| Recent / trending lists empty on first use | Both endpoints depend on `search_history` / `search_analytics` having data — expected for a fresh deployment |
| Clicking a suggestion doesn't navigate | Suggestions only fill the input and run the query; navigation happens from the **result list**, not from the suggestion row |
| "Clear All" button missing | It only appears when there are **2 or more** history rows for the current user/session |
| Stale results after locale switch | React Query invalidates on locale change; ensure the `useLocale()` value actually updated |
