# Browsing Files

Every file manager view — the admin library, the block image picker in [website-builder-v2](/docs/knowledgebase/filemanager-module/website-builder-integration), the lesson asset picker — is driven by a single endpoint that returns a paginated list of items inside a folder.

## Endpoint

- **Endpoint:** `GET /v1/admin/files`
- **Auth:** `AuthMiddleware` + `file.view` permission (see [Roles & Permissions](/docs/knowledgebase/filemanager-module/roles-and-permissions))
- **Tenant scope:** Every query is automatically filtered by the caller's `tenant_id`

## Query Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `dir_id` | UUID | Parent directory ID. Omit or use empty string to list the **root** |
| `page` | int | Page number (1-based, default `1`) |
| `per_page` | int | Items per page (default `20`) |
| `search` | string | ILIKE substring match on `name` |
| `sort_by` | string | One of `name`, `type`, `created_at`, `updated_at`, `size_in_bytes` |
| `sort_dir` | string | `asc` or `desc`. Default: folders first, then alphabetical |

Invalid `dir_id` values return **400 Bad Request** with `"Invalid directory ID format. Please provide a valid UUID."`.

## Response Shape

The response is a standard paginated envelope:

```json
{
  "success": true,
  "message": "Directory contents retrieved successfully",
  "data": [
    {
      "id": "0190cf2c-...",
      "name": "images",
      "item_type": "folder",
      "path": "/lesson-assets/images",
      "mime_type": "",
      "size_in_bytes": 0,
      "metadata": null,
      "created_at": "2025-04-14T10:12:00Z"
    },
    {
      "id": "0190cf2d-...",
      "name": "cover.jpg",
      "item_type": "file",
      "path": "/lesson-assets/images/cover.jpg",
      "mime_type": "image/jpeg",
      "size_in_bytes": 482119,
      "metadata": {},
      "created_at": "2025-04-14T10:12:40Z"
    }
  ],
  "pagination": {
    "page": 1,
    "per_page": 20,
    "total": 42,
    "total_pages": 3
  }
}
```

The response message is **"Root directory contents retrieved successfully"** when `dir_id` is omitted and **"Directory contents retrieved successfully"** otherwise.

## Item Type Discriminator

Each row in the `data` array has an `item_type` field:

| `item_type` | Meaning |
|-------------|---------|
| `"folder"` | A directory. `mime_type` is empty, `size_in_bytes` is 0, and the frontend should navigate into it on click |
| `"file"` | A file. `mime_type` drives the icon/preview choice and `size_in_bytes` is populated |

Both types share the same `id`, `name`, `path`, `created_at`, and `metadata` fields — they come from the same `media` table (see [index](/docs/knowledgebase/filemanager-module/index#data-model)).

## Default Sort Order

When `sort_by` is omitted, the server returns **folders first (desc by type), then alphabetical by name**. This matches classic file-explorer behaviour and is what the UI expects without explicit sort controls.

## Soft-Deleted Items

Every query automatically filters `WHERE deleted_at IS NULL`. Soft-deleted items **never appear** in browse results — see [File Management](/docs/knowledgebase/filemanager-module/file-management#soft-delete-vs-hard-delete) for what happens on delete.

## Navigation Pattern

The frontend maintains navigation state in React (not in the URL):

1. The root call: `GET /v1/admin/files?page=1&per_page=50`
2. User clicks a folder with `item_type = "folder"` → re-fetch with `dir_id={that_folder_id}`
3. Breadcrumb is built client-side from the `path` field of the current folder

The `@softimist/filemanager` package ships a folder tree sidebar, a breadcrumb trail, and a search bar that all hit this same endpoint.

## Search

`search=cover` performs a case-insensitive substring match against `name` inside the current `dir_id`. It does **not** search recursively into subfolders — if you want global search, pass `dir_id=<nil>` (root) and scan results.

## Pagination Limits

There is no hard maximum on `per_page` at the handler level, but:

- **Recommended UI default:** `20–50` items
- **Practical maximum:** `200` — above this, render time in the browser dominates

The `pagination.total` and `pagination.total_pages` fields let the UI render "Page X of Y" without a second call.

## Permissions

Both `GET /v1/admin/files` and `GET /v1/files/preview-*` require the `file.view` permission on the admin surface. On the public `/v1/files/preview-*` routes there is no auth — anyone with a file ID or path can fetch a redirect URL (tenant context is still derived from headers/domain, so cross-tenant access is blocked).

## Troubleshooting

| Issue | Solution |
|-------|----------|
| "Invalid directory ID format" | `dir_id` must be a valid UUID. Omit it to list the root |
| Empty list unexpectedly | Check that `deleted_at IS NULL` — the item may have been soft-deleted |
| Folder I created isn't showing | Make sure the response was 200. Also check `parent_id` — a folder created in root won't appear inside another folder |
| 403 Forbidden | Your role is missing `file.view` — see [Roles & Permissions](/docs/knowledgebase/filemanager-module/roles-and-permissions) |
| Very slow response on deep folders | Reduce `per_page`, or ensure the `idx_media_parent` and `idx_media_full_path` indexes haven't been dropped |
| Search ignores subfolders | Intentional — search scope is the current `dir_id` only. Use root (`dir_id` omitted) to search globally |
