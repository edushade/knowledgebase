# File Preview & Download

The file manager exposes four preview endpoints — two **ID-based**, two **path-based**, each with an admin (authenticated) and a public (unauthenticated) variant. By default they issue a **307 Temporary Redirect** to a presigned S3 URL; with `?mode=inline` they stream the bytes through the service.

## Endpoints

| Method | Path | Auth | Use |
|--------|------|------|-----|
| `GET` / `HEAD` | `/v1/admin/files/preview-id/{file_id}` | `AuthMiddleware` + `file.view` | Admin preview by UUID |
| `GET` / `HEAD` | `/v1/admin/files/preview-path/*filepath` | `AuthMiddleware` + `file.view` | Admin preview by full path |
| `GET` / `HEAD` | `/v1/files/preview-id/{file_id}` | None | Public preview by UUID |
| `GET` / `HEAD` | `/v1/files/preview-path/*filepath` | None | Public preview by full path |

> **Tenant scope:** even the public variants are tenant-scoped — the `tenant_id` is derived from request headers/domain by the `TenantMiddleware`. A file's ID cannot be used to fetch it from a different tenant.

## Preview by File ID

```
GET /v1/files/preview-id/0190d1e5-.....
```

**Response (default mode):** `307 Temporary Redirect` → a presigned S3 URL valid for **30 minutes**. The browser follows the redirect and downloads directly from S3.

**Response (`?mode=inline`):** `200 OK` with the file bytes streamed in the response body. The `Content-Type` header is set from the stored `mime_type`, and `Cache-Control: public, max-age=86400` is added.

## Preview by Path

```
GET /v1/files/preview-path/lesson-assets/images/cover.jpg
```

The `*filepath` Gin wildcard captures the **full path after `/preview-path/`** — including any nested subdirectories — and looks up the file by `full_path` inside the current tenant.

| Input | Lookup |
|-------|--------|
| `/preview-path/cover.jpg` | Root-level `cover.jpg` |
| `/preview-path/lesson-assets/images/cover.jpg` | Nested path as stored |

This variant is used by rich-text editor output (stored with `full_path`-relative URLs) and by the [website-builder-v2](/docs/knowledgebase/filemanager-module/website-builder-integration) when it persists paths instead of IDs.

## Redirect vs Inline Mode

The query parameter `mode` picks the delivery mechanism:

| Mode | Transport | Status | Best for |
|------|-----------|--------|----------|
| *(omitted — default)* | Browser fetches presigned URL from S3 | `307 Temporary Redirect` | Normal preview / download — S3 does the heavy lifting, service just signs |
| `?mode=inline` | Service streams bytes to the client | `200 OK` with `Content-Type` and `Cache-Control: public, max-age=86400` | Cases where you can't follow redirects (e.g. some `<img>` proxies, test suites) |

The **redirect** mode is strongly preferred in production — it costs the service no bandwidth after the redirect.

## Presigned URL Lifetime & Caching

| Property | Value |
|----------|-------|
| **Presigned URL expiry** | 30 minutes |
| **In-process URL cache** | `go-cache`, keyed by `bucket_key`, TTL = 5 minutes |
| **Cache scope** | Per service instance (not shared across replicas) |

The cache means that repeat requests for the same file within 5 minutes reuse the same presigned URL — the client will still succeed because the URL itself is valid for 30 minutes. This drops S3 presigning load on busy file managers. See [Security & Limits](/docs/knowledgebase/filemanager-module/security-and-limits#presigned-url-caching) for implications.

## HEAD Requests

Every `GET` preview route also responds to `HEAD`. This is useful for:

- Link-checkers / broken-image detection (no body needed)
- CDN `If-Modified-Since` probes
- Frontend pre-flight before switching between image/video players

The handler treats `HEAD` identically to `GET` — the redirect or headers are emitted but Gin elides the body.

## Use from the Frontend

The `@softimist/filemanager` package exposes a `getFileUrl(fileId)` helper that applies the configured `assetBaseUrl` prefix. In production (tenant-relative) the prefix is empty, so file URLs end up as `/v1/files/preview-id/{file_id}`. On localhost/dev the prefix is `apiBaseUrl` so URLs become fully absolute.

Typical usage from a React component:

```tsx
<img src={getFileUrl(file.id)} alt={file.name} />
```

The browser receives the `307` and follows it to S3 — no extra JavaScript needed.

## Error Behaviour

| Condition | Status | Message |
|-----------|--------|---------|
| Missing `file_id` param | `400` | "File ID is required. Please provide a valid file ID in the URL path." |
| Invalid UUID in `file_id` | `400` | "Invalid file ID format. Please provide a valid UUID." |
| File not found / soft-deleted | `404` | "File not found. The requested file does not exist or has been deleted." |
| Storage failure (signing) | `500` | "Failed to generate file preview URL. Please try again later." |
| Storage failure (inline) | `500` | "Failed to stream file." |

Soft-deleted files (`deleted_at IS NOT NULL`) return `404` just like missing files — previously-shared URLs stop working the moment a file is deleted.

## Cross-Tenant Safety

A file ID from tenant A cannot be previewed from a request scoped to tenant B. The lookup query includes `WHERE tenant_id = <caller-tenant>`, so foreign IDs simply return `404`. This guarantee applies to both the admin and public preview routes.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| `404` but file exists in DB | Check `deleted_at` — the file may be soft-deleted. Also confirm the request's tenant matches the file's `tenant_id` |
| `307` works but following URL fails with 403 | Presigned URL expired (30-minute window). Re-hit the preview endpoint |
| Stale image after re-upload | The 5-minute in-process URL cache is still serving the old presigned URL. Wait or restart the service |
| `?mode=inline` returns garbled content | `Content-Type` may be wrong for this file (stored at upload time) — update `mime_type` via migration, or use the redirect mode |
| Path lookup fails with leading/trailing slashes | The Gin wildcard preserves the literal path. Make sure your frontend doesn't double-escape slashes or strip the leading `/` from the stored `full_path` |
| CDN caches a broken URL | Set up your CDN to not cache 307 responses, or shorten the CDN TTL to be less than 30 minutes |
