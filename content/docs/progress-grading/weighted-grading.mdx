description: "Deciding how much each assessment is worth — the weights editor, the rule that they must total 100%, and optional bonus subjects."

A weight is how much an assessment counts towards the programme's result. A final exam
at 50% matters as much as everything else put together.

Weights are set on a programme's **Grading** tab, in the weights editor, and they belong
to that programme — a course's weights describe its own items, a learning path's
describe the courses inside it.

<WhoCan roles="Admin" />

## The rule: weights share one whole

Each gradable item takes a weight from 0 to 100, and **together they must equal exactly
100%**. The editor will not let you save until they do, and it tells you how far off you
are.

| Assessment | Weight |
|---|---|
| Weekly quizzes | 20% |
| Assignment | 30% |
| Final exam | 50% |
| **Total** | **100%** |

If you set no weights at all, the programme falls back to a plain average — every item
counting the same.

## Letting the editor do the arithmetic

Typing twelve weights that come to exactly 100% by hand is miserable, so the editor can
do the sharing for you.

**Auto-distribute** is a switch at the top. With it on:

- Any weight you **type yourself is pinned** — the editor leaves it exactly where you
  put it.
- Every item you have **not** touched shares whatever is left, equally, so the total
  stays at exactly 100%.
- Clearing a weight **unpins** it, and it goes back to sharing the remainder.

So the way to use it is: switch it on, type the two or three weights you actually care
about, and let the rest settle themselves.

| Control | What it does |
|---|---|
| **Auto-distribute** (switch) | Turns the sharing on or off. It asks before it changes anything, because turning it on rewrites every weight you have not pinned. |
| **Distribute equally** | Resets all pins and splits 100% evenly across every gradable item. It asks first — it overwrites what you typed. |
| **Reset to auto** (on one row) | Unpins that one item so it shares the remaining weight again. On an alternative, it goes back to matching its primary's weight. |
| **Save Program Weights** | Saves. Greyed out until the total is exactly 100%. |

<Callout type="info">
**If your pinned weights already come to more than 100%,** the editor says so and names
the figure — there is nothing left for the other items to share. Reduce a pinned weight
and the rest settle again.
</Callout>

## Setting the progression rule from here

Beside each semester on this page there is a **Progression** control — how many of that
semester's subjects a learner must pass before continuing to the next one.

It lives here because this is where you are already deciding what the semester is made
of, and because the rule counts the same subjects you are weighting: those marked
**Full**, not the bonus ones. Once set, the control reads **Pass 4 to continue**.

See [Progression](/docs/knowledgebase/enrollment-access/progression).

## Alternative assessments in the weights list

When two assessments are interchangeable — a main exam and its makeup — they form one
slot, and the slot's weight sits on the **primary** member. The other members appear in
the list too, with a link to their primary, but:

- Their weight may be **at most** their primary's. The editor refuses more.
- Their weight is **not** part of the programme's 100% total.

See [Alternative assessments](/docs/knowledgebase/assessments/alternative-assessments).

## Optional subjects: Full and Bonus

If the programme's **Result Policy** is set to **Average with bonus**, each item gains a
**Full / Bonus** choice:

| Choice | What it means |
|---|---|
| **Full** | The item's whole score counts, and its weight is part of the 100% total. |
| **Bonus** | Only what the item scores *above* the bonus threshold is added, and its weight is not counted in the total. |

A bonus item can raise a learner's result but never lower it — which is what makes an
optional subject safe to offer. With bonus items in play, the "must total 100%" rule
applies only to the items marked **Full**.

The threshold and the highest result a programme can reach are set beside the result
policy. See
[Course grading setup](/docs/knowledgebase/progress-grading/course-grading-setup).

## What happens to an unmarked assessment

This is where weights and the rest of the setup meet, and it is worth being clear about:

- With **Treat Ungraded Items as Zero** off (the default), an unmarked assessment is
  left out and **its weight is shared among the ones that have been marked**. A learner
  who has sat only the 20% quiz is marked out of that quiz alone.
- With it on, an unmarked assessment counts as a real zero.

The weights are the same either way. What changes is the denominator.

## After you change weights

Results already recorded do not move on their own. Run **Calculate All Grades** on the
programme's learner grades screen so everyone is judged by the new weights.

## Common questions

<Accordions type="single">

<Accordion title="Save is greyed out.">
The total is not exactly 100%. The editor shows the running total and how far off it is.
If bonus items are in play, only the items marked **Full** count towards that 100%.
</Accordion>

<Accordion title="The editor keeps changing weights I did not touch.">
That is auto-distribute doing its job: the items you have not typed into are sharing
whatever is left. Type a weight into one and it is pinned — the editor will not move it
again. Switch auto-distribute off if you would rather set all of them yourself.
</Accordion>

<Accordion title="I typed a weight and then cleared it, and it changed on its own.">
Clearing a weight unpins the item, so it goes back to sharing the remainder. Type 0 if
you want it pinned at nothing.
</Accordion>

<Accordion title="I want one quiz not to count at all.">
Give it a weight of 0. It still appears in the course and learners still take it; it
simply contributes nothing to the result.
</Accordion>

<Accordion title="A course inside my learning path is not using my weights.">
It should not. A path's weights describe the path's own items. A course inside it uses
its own grading setup; if it has none, it falls back to a plain average of its content —
it never borrows the path's weights, because those weights point at sibling items, not
at that course's lessons.
</Accordion>

<Accordion title="Why can a supplementary assessment not weigh more than its primary?">
Because the slot's weight belongs to the primary. A makeup exam that counted for more
than the exam it replaces would reward missing the original.
</Accordion>

<Accordion title="Where do I set weights for a batch?">
On the batch's own Grading tab. A batch with no setup of its own follows the course's.
</Accordion>

</Accordions>
