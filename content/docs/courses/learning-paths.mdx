A learning path strings several courses together into one thing a learner buys, works
through and finishes. The path has its own price, its own progress, its own result and
its own certificate — the courses inside it keep theirs.

<WhoCan roles="Admin, Instructor" />

## When a path is the right answer

Use a learning path when the courses only make sense together — a diploma, a career
track, a syllabus of four subjects.

Do not use one when you just want to sell three courses at a discount. That is a
[bundle](/docs/knowledgebase/selling-payments/bundles): a bundle is a price on several
things, a path is a programme in its own right.

## Building one

A learning path is four steps, reached from <Path>Learning Paths > Add Learning Path</Path>.

### Step 1 — details

Title, **Slug**, **Description**, **Summary**, **Thumbnail**, **Preview Media**,
**Categories** (required), **Instructors**, **Duration**, **Difficulty Level** and
**Language**. The **Summary** is the short version shown in listings; the description is
the long one on the path's own page.

### Step 2 — the content

<Screenshot
  src="/kb/courses/learning-path-builder.png"
  alt="The learning path builder with Curriculum, Grading, Drip Schedule and Prerequisites tabs, buttons to add a Stage, Course or Quiz, and Stage 1 containing a course and a quiz"
  caption="A path is built from stages, and a stage holds whole courses — not lessons."
/>

Three buttons add to a path:

| Button | What it adds |
|---|---|
| **Stage** | A grouping — "Year 1", "Foundation". Stages hold everything else. |
| **Course** | A whole existing course, picked from your catalogue. |
| **Quiz** | A test that belongs to the path itself, not to any one course — a final exam across the whole programme. |

Everything else works as it does in a course: drag to reorder, a **Published** switch
per row, and a **⋯** menu per item. See
[The course builder](/docs/knowledgebase/courses/curriculum-builder).

The same four tabs sit across the top — **Curriculum**, **Grading**, **Drip Schedule**
and **Prerequisites** — and they apply to the path as a whole.

### Step 3 — assign learners

A list of your people with **Select All** and **Assign**, and the learners already on the
path beside it. This enrols people directly, without a purchase. For anything beyond a
handful, see
[Admin and bulk enrollment](/docs/knowledgebase/enrollment-access/admin-and-bulk-enrollment).

### Step 4 — settings

The same settings a course has: **Enrollment Open**, **Maximum Enrollments**,
**Enable Certificate**, **Enable Transcript**, **Certificate Code**, **Enable Rating**, **Learning Outcomes**, **Requirements** and the
**Completion Message**. See
[Course settings](/docs/knowledgebase/courses/course-settings), which explains each one.

## How a path and its courses fit together

- **Progress** on the path is worked out from the courses inside it.
- **Grading** on the path is set on its own **Grading** tab, and can weight the courses
  differently — see [Weighted grading](/docs/knowledgebase/progress-grading/weighted-grading).
- **A certificate** can be awarded for the path, for a course inside it, or both.
- **A course can be in more than one path**, and in your catalogue on its own at the
  same time.

<Callout type="warn">
A course inside a path is the same course, not a copy. Edit it and every path containing
it changes. That is usually what you want — but it is why renaming a course can surprise
people.
</Callout>

## Mixing self-paced and scheduled courses

A path can hold both. A self-paced primer can sit in front of a cohort-based batch, so a
learner reads the primer while waiting for the batch to start. Each course keeps its own
behaviour inside the path.

## Common questions

<Accordions type="single">

<Accordion title="What is the difference between a learning path and a bundle?">
A **bundle** is a price on several items bought together; the learner ends up with
separate enrolments and separate certificates. A **learning path** is one programme with
one enrolment, one progress figure, one result and one certificate. If the learner should
feel they joined *one* thing, use a path.
</Accordion>

<Accordion title="Does a learner have to finish the courses in order?">
Only if you make them. Order in the builder is presentation; to actually lock course two
until course one is done, set a prerequisite. See
[Prerequisites](/docs/knowledgebase/enrollment-access/prerequisites).
</Accordion>

<Accordion title="A learner is in the path and also bought one of its courses separately.">
They have two enrolments, and they are kept apart on purpose: work done in the path
counts towards the path, and work done in the standalone course counts towards that.
Progress is tracked per enrolment. See
[Progress tracking](/docs/knowledgebase/progress-grading/progress-tracking).
</Accordion>

<Accordion title="Can a path have batches?">
No. Batches belong to cohort-based courses. A path can *contain* a cohort-based course,
and the learner joins a batch of that course inside the path.
</Accordion>

<Accordion title="Can I add a quiz straight to the path?">
Yes — **+ Quiz** on the builder adds a quiz that belongs to the path rather than to any
of its courses. Use it for a final exam that covers the whole programme.
</Accordion>

</Accordions>
